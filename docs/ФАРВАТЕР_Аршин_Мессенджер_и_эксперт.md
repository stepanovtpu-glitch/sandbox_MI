# ФАРВАТЕР: бот Яндекс Мессенджера и «Метрологический эксперт»

**Статус:** локально реализовано; токен, боевой запуск и live-проверка не выполнены.  
**Проверено по проекту:** 15.11.2026.

## Опыт АТЛАСа и выбранная схема

АТЛАС подтвердил рабочие локальные образцы: отправка сообщений и файлов через Bot API применяется в проектах, а входящие сообщения уже принимаются отдельным polling-ботом МТР с сохранением `update_id`. В GasMeter до этой доработки была только отправка уведомлений о согласовании.

ФАРВАТЕР использует тот же документированный механизм polling в отдельном worker-контейнере. Это позволяет не менять существующий канал уведомлений и не добавлять публичный webhook. Запуск worker отделён Compose-профилем `messenger`; в штатном запуске приложения он не стартует.

## Возможности

### Поиск поверки в ФГИС «Аршин»

Команда в личном чате:

```text
/поверка заводской_номер [номер_типа_СИ]
```

Бот ищет по заводскому номеру через внешний публичный read-only интерфейс Росстандарта, после ответа повторно отбирает только точные совпадения. Показывает тип и номер СИ, номер типа, дату поверки, срок действия, пригодность, номер документа, поверителя и официальную ссылку. Если реестр не отвечает, бот сообщает об этом без вывода о действующем сроке.

К сообщению прикладывается сформированная PDF-копия открытых полей. Она имеет заметную пометку: **не является официальным свидетельством или заверенной выпиской**. Отдельный файл свидетельства/протокола из реестра текущая реализация не скачивает: это требует подтверждённого официального маршрута и формата вложения. Для проверки и юридически значимого источника открывается запись Росстандарта.

### «Метрологический эксперт»

В приложении появился отдельный экран, в боте принимаются `/эксперт вопрос` и обычный текст. Поиск источников сначала выполняется локально по OCR-текстам действующих МИ. Корпоративная LLM получает только найденные фрагменты; ответ должен сопровождаться файлами-источниками. OCR-фрагменты без подтверждения полей человеком помечаются как неподтверждённые. Если подходящий фрагмент не найден, система не просит модель отвечать «из общих знаний».

LLM не распознаёт сканы, не вычисляет коэффициенты, не определяет действительность поверки и не меняет вердикт подбора. Ответ эксперта — справочный, его нужно сверять с исходным документом.

## Доступ и обработка

- Обслуживаются только личные чаты; групповые сообщения игнорируются.
- Логин отправителя Яндекса сопоставляется с активным пользователем GasMeter. Различающиеся логины связываются через `GASMETER_YM_USER_MAP`.
- Токен читается из окружения worker и не возвращается API/логами.
- Смещение polling хранится в общей базе; worker рассчитан на один экземпляр.
- Файлы МИ worker читает только для поиска, том подключён read-only.
- В audit log сохраняется событие использования, модель и число источников; текст вопроса не записывается.

## Включение на сервере

Пока не выполнять: реальный токен/сопоставление пользователей не предоставлены и производственный запуск не проверен.

После передачи настроек администратором:

1. Перенести обновлённый образ backend и миграцию схемы.
2. Внести `GASMETER_YM_TOKEN` и, если нужно, JSON-сопоставление логинов в защищённый `.env`.
3. Убедиться, что сервер разрешает исходящий HTTPS к Bot API Яндекса и публичному интерфейсу ФГИС «Аршин».
4. Запустить отдельно `docker compose --profile messenger up -d messenger-bot`.
5. Проверить ответы от тестового пользователя, точный номер СИ, отсутствие совпадений, непригодность, недоступность источника и формирование PDF-копии.
6. Не включать пользователей в общий доступ, пока метролог не сверит поля и формат выдачи.
