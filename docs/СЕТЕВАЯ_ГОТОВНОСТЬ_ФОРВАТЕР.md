Наличие TCP-соединения с «Аршином» **не означает**, что API работает: сейчас не проходит TLS. Причина тайм-аута не установлена и не должна называться ошибкой ФОРВАТЕРА или межсетевого экрана без дополнительной диагностики. До успешного запроса программа сообщает о недоступности источника и не объявляет плановую дату из выгрузки подтверждённой поверкой.

Корпоративные заводские номера, выгрузки и ключи не передаются на внешний стенд для обхода сетевой проблемы. После восстановления обоих соединений необходимы контрольные запросы, сверка записи с официальным источником, проверка отрицательного ответа и проверка поведения при сбое.

## Повторная проверка 23.11.2026 после релиза 0.2.18

- АРХИМЕД: DNS `fgis.gost.ru` разрешается; TCP устанавливается быстро, TLS не завершается за 12 секунд (`curl` HTTP 000). Это не доказывает причину сбоя.
- Внешний сервер и рабочий ПК: TCP/443 к тому же официальному имени не устанавливается за 4 секунды. Открыть официальный интерфейс через исследовательский веб-клиент также не удалось из-за тайм-аута. Замена адреса ФГИС сторонним сайтом не выполнялась.
- В окружении хоста, контейнера ФОРВАТЕРА и РИТМа переменные HTTP(S)-прокси отсутствуют. В контейнерах ФОРВАТЕРА и РИТМа URL и модель LLM не заданы; прямое соединение АРХИМЕДа с прежним адресом `10.61.157.1:11434` по-прежнему отвергается. Локальный порт 11434 на АРХИМЕДе также не отвечает.
- Яндекс Bot API остаётся независимым от этих двух соединений; проверка отправки по маршруту РИТМ → ФОРВАТЕР выполнена отдельно. Живое входящее сообщение владельца по-прежнему не наблюдалось.

Следующий сетевой шаг — проверить доступность официального узла ФГИС у оператора сети и актуальный адрес/порт корпоративной LLM у владельца сервиса. До успешного запроса нельзя объявлять онлайн-проверку поверки или ответ LLM работающими.

**Уточнение по LLM.** В файле доступа к серверу из `C:\pass` прямо указано, что прежний адрес `10.61.157.1` остановлен 08.09.2026. В доступных проектных настройках действующий внутренний адрес не найден. Переменные ФОРВАТЕРА оставлены пустыми; отправка рабочих данных на внешний LLM-шлюз не включалась. Владелец сервиса должен сообщить новый URL и модель.

**Живой входящий маршрут бота проверен.** Из авторизованного Яндекс Мессенджера владельца отправлена одна команда `/состояние` без номера. РИТМ записал реальный `update_id` и доставил его в защищённую очередь, ФОРВАТЕР завершил обработку с нулём попыток повтора, ответ «Укажите после команды заводской номер…» получен в этом же чате. Отдельная read-only проверка в корпоративной БД нашла по точному заводскому номеру одну строку последнего снимка от 20.11.2026 со статусом плановой даты `within_date`; номер и строка не передавались на внешний сервер. Это проверяет маршрутизацию и локальный поиск, но не онлайн-ответ «Аршина» или отправку реального свидетельства.
