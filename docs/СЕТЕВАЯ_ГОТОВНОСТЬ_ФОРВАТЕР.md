# Сетевая готовность онлайн-функций ФОРВАТЕРА

**Диагностика 23.11.2026, источник — сервер АРХИМЕД 10.224.120.1.**

| Служба | Проверка | Результат | Что требуется |
|---|---|---|---|
| ФГИС «Аршин», `fgis.gost.ru:443` | DNS, TCP, HTTPS к публичному интерфейсу `/fundmetrology/eapi/vri` | DNS и TCP доступны; TLS-рукопожатие не завершилось даже за 15 секунд (`SSL connection timeout`, HTTP 000). На рабочем ПК TCP также не установился за 4 секунды. | Проверить доступность официального узла и прохождение TLS от АРХИМЕДа. После восстановления проверить реальный ответ API на контрольном заводском номере и его структуру. |
| Корпоративная LLM, `10.61.157.1:11434` | TCP к Ollama `/api/tags` | `ConnectionRefusedError`: на адресе и порту соединение отвергнуто. | Владелец сервиса должен проверить процесс Ollama, слушающий адрес, маршрут и правила доступа от 10.224.120.1. | Яндекс Мессенджер, `botapi.messenger.yandex.net:443` | TCP и HTTPS без токена | TCP и TLS доступны; HTTP 401 ожидаем без токена. Контрольная команда через очередь РИТМа обработана ФОРВАТЕРОМ и доставлена ботом. | Сетевого изменения для исходящих сообщений не требуется. Реальное входящее сообщение пользователя подтвердить отдельно. |

Наличие TCP-соединения с «Аршином» **не означает**, что API работает: сейчас не проходит TLS. Причина тайм-аута не установлена и не должна называться ошибкой ФОРВАТЕРА или межсетевого экрана без дополнительной диагностики. До успешного запроса программа сообщает о недоступности источника и не объявляет плановую дату из выгрузки подтверждённой поверкой.

Корпоративные заводские номера, выгрузки и ключи не передаются на внешний стенд для обхода сетевой проблемы. После восстановления обоих соединений необходимы контрольные запросы, сверка записи с официальным источником, проверка отрицательного ответа и проверка поведения при сбое.
