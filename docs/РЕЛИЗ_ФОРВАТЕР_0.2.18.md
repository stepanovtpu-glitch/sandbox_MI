# ФОРВАТЕР 0.2.18 — документы поверителя в карточке СИ и боте

**23.11.2026.** Метролог может приложить к конкретному экземпляру СИ PDF, полученный от организации-поверителя. Карточка сохраняет номер, дату, организацию и происхождение документа; скачивание контролирует SHA-256. Загрузка не меняет статус поверки и не выдаёт документ за данные ФГИС «Аршин».

Команда «Инженерной памяти» `/свидетельство заводской_номер [номер_типа_СИ]` отправляет приложенный PDF только при однозначном соответствии экземпляру. При одинаковых заводских номерах бот просит уточнить номер типа. В сообщении указано, что PDF приложен поверителем, а не получен из ФГИС. Для поиска записи в реестре остаётся команда `/поверка`.

Один архив образов с SHA-256 `deb12f21722cef3e6a684141641433faab54eb3b9ef2cf6aa82a3f32b49e4563` установлен на АРХИМЕДе и внешнем стенде после резервного копирования. На АРХИМЕДе подтверждены версия 0.2.18, схема БД 13, 48 312 строк выгрузки, работа bridge worker и запрет анонимной загрузки документа (HTTP 401). На внешнем стенде подтверждены версия 0.2.18 и HTTP 200; корпоративные данные туда не переносились. Маршрутизатор команд РИТМа обновлён до 1.17.3 и установлен из чистой копии отслеживаемых файлов.

Проверки: 171 тест backend, 144 теста РИТМа, TypeScript/Vite сборка. Локальная проверка интерфейса в браузере: форма открывается в карточке СИ, ширина 390 px без горизонтального переполнения; снимки находятся в `output/playwright/` и не входят в релиз.

**Границы проверки.** В продуктиве ещё нет приложенного подлинного PDF, поэтому реальная отправка такого файла ботом не проверена. Маршрут и отправка проверены тестом с локальным PDF. Автоматическая выгрузка свидетельства непосредственно из ФГИС не реализована: доступный интерфейс записи о поверке не следует выдавать за подлинное свидетельство. Сетевые соединения АРХИМЕДа с ФГИС и корпоративной LLM остаются недоступными; новая выгрузка ТОиР от источника не поступала. Эти пункты требуют отдельных проверок по живым данным.

**Усиление резервного копирования после выпуска.** Скрипт `deploy/backup.sh` теперь отдельно проверяет код завершения `pg_dump`, целостность SQL gzip и файлового tar, а затем публикует оба архива. Ошибка упаковки документов больше не маскируется. Новый скрипт установлен на обоих серверах с сохранением прежней версии для отката; контрольные запуски и чтение архивов прошли. Восстановление новой копии в отдельной временной БД подтверждено: на АРХИМЕДе 48 312 строк снимка, на внешнем стенде 216 МИ и 0 корпоративных строк; временные БД после проверки удалены. SHA-256 установленного скрипта: `529412a2fe779d41641ce03da4a0748f9729b467772dd61775a3b0820c2cd43e`. Расписание ежедневного копирования не менялось.

**Живой тест входящего сообщения.** После выпуска команда `/состояние` отправлена владельцем через его авторизованный клиент Яндекс Мессенджера; бот ответил в том же чате. РИТМ и ФОРВАТЕР подтвердили доставку и обработку по одному реальному `update_id` без повторов. Проверка с конкретным номером выполнена отдельно в корпоративной БД без публикации номера: одна строка последнего снимка от 20.11.2026 возвращена. Онлайн-сверка ФГИС и передача подлинного PDF пока не проверены.
