# ФОРВАТЕР 0.2.21 — защита даты периодической выгрузки

**23.11.2026.** Импорт ИС Метрология теперь отклоняет один и тот же XLSX, повторно предъявленный с другой датой среза. Такое повторное использование файла не доказывает, что источник сформировал новый снимок. Проверка действует при ручной предварительной проверке, публикации и плановом приёме из защищённой папки. Повтор файла с исходной датой остаётся идемпотентным.

Проверки: 175 тестов backend, сборка TypeScript/Vite, маршруты `/api/` и `/health` в веб-образе. На корпоративном сервере новое правило проверено без записи в базу на сохранённой реальной выгрузке: файл доступен, подмена даты отклонена. Исправленный релиз установлен на АРХИМЕДе и внешнем стенде после резервного копирования; на обоих подтверждены версия 0.2.21 и HTTP `/health`. SHA-256 архива образов: `60c7c61259b5e1f55ba4a7f1f31e6026c5ed04b12d1b2527a86d92c71885b156`.

**Границы.** Новый полный файл из ИС Метрология не поступил, поэтому автоматическое обновление по следующему реальному срезу ещё не проверено. Правило защищает от повторного использования идентичного файла с новой датой, но не подтверждает подлинность происхождения произвольного нового XLSX. Сетевой доступ к ФГИС «Аршин» и действующий адрес корпоративной LLM остаются открытыми вопросами.

**Уточнение утилиты отправки после выпуска образов.** Локальный `scripts/send_metrology_snapshot.py` теперь проверяет дату по часовому поясу ИНК (`Asia/Irkutsk`) и разбирает XLSX без обращения к локальной БД. Это позволяет отправить с ПК корректный срез нового производственного дня, когда местная календарная дата ещё предыдущая. Скрипт проверен отдельным тестом и общим прогоном 176 тестов; серверные образы 0.2.21 не менялись. На АРХИМЕДе подтверждены активный cron, четыре записи запуска в журнале и последний успешный повтор уже опубликованного файла без ошибок.
