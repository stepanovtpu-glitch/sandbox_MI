# ФОРВАТЕР 0.2.17 — устойчивый плановый импорт

**23.11.2026.** Плановый приём полных XLSX-выгрузок проверяет повторный SHA-256 по всей таблице импортов, а не только по 30 строкам списка на экране. Сохранённый во входящей папке старый файл не начинает ошибочно останавливать ежечасное задание после накопления истории. Дата среза сравнивается с производственным днём, используемым остальной логикой импорта.

После резервного копирования один архив образов установлен на корпоративном АРХИМЕДе и внешнем стенде. SHA-256: `31cc6e4db12fe59ba6591879234e45b921b05f13a8c686332647a44dd3f2b152`. На АРХИМЕДе подтверждена версия 0.2.17, 48 312 строк выгрузки и ручной прогон планового задания: 0 новых публикаций, 1 ранее импортированный файл, 0 ошибок. Worker бота работает. На внешнем стенде подтверждены версия 0.2.17, HTTP 200, 0 корпоративных строк и 0 интеграционных клиентов.

Проверки: 169 тестов backend; регрессионный сценарий охватывает повторный файл после 31 более позднего импорта и производственную дату. Подключение новой выгрузки от источника, запрос к ФГИС «Аршин» и ответ корпоративной LLM остаются непроверенными по живым данным: новых файлов нет, а соединения с двумя службами из серверного контура нет.

**Дополнительная проверка после установки.** Через очередь РИТМа введена контрольная команда `/состояние` без заводского номера для личного чата владельца. РИТМ подтвердил доставку (`sent=1, failed=0`), запись ФОРВАТЕРА завершилась (`status=done, attempts=0`), ответ был принят Bot API. В чат отдельно отправлено пояснение о характере проверки. Смещение `getUpdates` не изменялось; тест не выдаётся за реальное входящее сообщение пользователя и не проверяет поиск конкретного СИ.

Отдельный интеграционный тест РИТМа проверил обработку входящего пакета `getUpdates`: новая личная команда ставится в очередь, групповая и устаревшая не ставятся, смещение сохраняется. В полном наборе РИТМа — 144 пройденных теста. Это подтверждает код входящего маршрута, но не заменяет наблюдение реального сообщения пользователя.
