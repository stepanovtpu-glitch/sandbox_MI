# ФОРВАТЕР: договор чтения метрологического снимка v1

Пилотный внутренний API выдаёт **кандидатов** из последней полной выгрузки ИС Метрология/ТОиР. Он не подтверждает физическую идентичность СИ и не объявляет поверку действующей по плановой дате. Ответ нужно рассматривать как исходные данные для сверки, а не как разрешение на эксплуатацию.

## Запрос

`GET /api/integration/v1/metrology/lookup?serial=<точный заводской номер>`

Необязательные уточнения: `organization=<точное название>` и `metrology_code=<точный код 1С Метрология>`. Заводской номер обязателен; частичный поиск, похожие номера и поиск по наименованию здесь не выполняются. Заголовок `X-Forvater-Key` содержит отдельный ключ конкретного потребителя. Без него ответ — 401. Ключ не входит в пользовательские сессии и не передаётся в URL.

## Ответ

- `contract_version`: `1.0`;
- `snapshot`: ID, дата среза, время загрузки, имя и SHA-256 исходного XLSX, число строк и состояние свежести;
- `match_status`: `no_snapshot`, `not_found`, `single_candidate` либо `ambiguous`;
- `total_matches`, `truncated` и не более 20 `candidates`;
- кандидат: строка источника, код 1С, GUID ТОиР, организация, заводской номер, наименование и место, вид работы, срок на дату среза и на операционную дату;
- `verification_status: not_confirmed_by_this_source`, `identity_status: candidate_only` — обязательные признаки. Дата ТОиР не превращается в подтверждение из ФГИС «Аршин».

При нескольких строках по номеру договор возвращает все доступные кандидаты в пределах лимита и `ambiguous`; потребитель не должен выбирать первую строку молча. При устаревшем снимке поле `snapshot.freshness` указывает возраст и настроенный порог. Если порог не согласован, статус `threshold_unset`.

## Доступ и эксплуатация

Каждому потребителю выдаётся отдельный ключ; в PostgreSQL хранится только SHA-256. Создание ключа проводится через SSH на корпоративном сервере; образец пилотного клиента создаёт `scripts/provision_forvater_integration.py`, открытый ключ хранится локально в `C:/pass`. Управляющего HTTP-маршрута, возвращающего секрет, нет. Ключ можно отключить через серверную функцию `disable_client`. Каждый запрос записывается в аудит с ID клиента и числом совпадений без значения ключа.

Внешний стенд не содержит корпоративной выгрузки и не предназначен для выдачи этих данных. До включения потребителей необходимо согласовать мастер-ID физического СИ, правила полных/частичных выгрузок, SLA свежести, права клиентов и сетевой маршрут с TLS. Нынешний договор не соединяет автоматически запись Аршина с кандидатом ТОиР.
