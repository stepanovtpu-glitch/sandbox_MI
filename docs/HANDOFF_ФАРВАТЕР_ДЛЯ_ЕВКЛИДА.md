# ФОРВАТЕР для ЕВКЛИДА

## Актуализация 23.11.2026 — релиз 0.2.20

На АРХИМЕДе и внешнем стенде установлен **ФОРВАТЕР 0.2.20**. Бот «Инженерная память» использует снимок ИС Метрология и показывает плановый срок отдельно на сегодня и на дату среза, возраст данных и состояние порога свежести. Живой входящий маршрут бота проверен; формат нового ответа проверен тестами, новое реальное сообщение не отправлялось. Проверены 175 тестов backend, веб-сборка, итоговый архив образов и HTTP `/health` на обоих серверах. История и ограничения описаны в [релизе 0.2.20](РЕЛИЗ_ФОРВАТЕР_0.2.20.md).

**Открыто:** официальный API ФГИС «Аршин» недоступен по сети; действующий адрес корпоративной LLM неизвестен; новый полный файл выгрузки источником не предоставлен; подлинный PDF свидетельства в продуктив не загружен. На АРХИМЕДе последняя выгрузка содержит 48 312 строк на 20.11.2026, порог свежести не утверждён. Внешний стенд корпоративную выгрузку не содержит. Для ЕВКЛИДа нельзя интерпретировать плановую дату ТОиР как подтверждение поверки или обещать онлайн-проверку до успешной сверки с ФГИС.

## Актуализация 23.11.2026 — релиз 0.2.12

Модуль переименован и выпущен как **ФОРВАТЕР 0.2.12** на корпоративном АРХИМЕДе и внешнем стенде. Корпоративный контур содержит 216 МИ, 224 OCR-текста, 231 проверенный исходный PDF и снимок ИС Метрология на 48 312 строк; 622 версии МИ привязаны к сканам с SHA-256. Внешний контур — 216 МИ без корпоративного снимка, OCR и сканов. Доступны поиск по точному заводскому номеру, списки сроков, разбор повторов GUID, CSV с происхождением данных, ручная загрузка и ежечасный приём полного файла из защищённой папки. Срок из выгрузки показывается отдельно на дату среза и на сегодня; возраст снимка виден, порог свежести пока не утверждён. Пилотный API v1 отдаёт точные совпадения, происхождение снимка и признак неоднозначности по отдельному ключу; тестовый запрос через SSH на АРХИМЕДе прошёл, реальные потребители ещё не подключены. Мобильное меню проверено на 390 px; внешняя авторская метка теперь загружается. Смена пароля и отключение пользователя отзывают сессии. «Метрологический эксперт» показывает OCR-фрагменты и исходный скан; LLM и канал Яндекс Мессенджера там не подключены. Успешная связь с Аршином не подтверждена. Автоматическая доставка файла из 1С, подтверждение поверки из Аршина и официальный документ ещё не введены в эксплуатацию. Для публикации в ЕВКЛИДЕ использовать эту границу готовности и [релиз 0.2.12](РЕЛИЗ_ФОРВАТЕР_0.2.12.md). Ниже сохранён исторический срез 15.11.2026; его технические статусы устарели.

## Краткое назначение

Общий метрологический источник для методик и их версий, средств измерений и комплексов СИГК/СИКН/СИКНС, доказательств поверки, применимости МИ, истории статуса и API для подключённых систем. Это архитектурное предложение; промышленный сервис, общий API и интеграции ФАРВАТЕРА не подтверждены.

## Границы функций

- ФАРВАТЕР: структурированные версии МИ, метрологические связи СИ и комплексов, доказательства поверки, применимость, история и выдача статуса с источником/временем.
- СИЛЬВЕР: собственная НСИ, проверенный слой и качество фактических тегов/телеметрии.
- АРХИМЕД: расчёт дебита и производственных суток.
- ГЕРОН: прогноз отказов; модуль утечек: выявление утечек.
- РИТМ: заявки, сроки исполнения и результат работ. Закрытие заявки не подтверждает поверку.
- МТР: каталог/наличие/закупки; TechDoc: документы и поиск при подтверждении связи.
- АТЛАС: мастер реестров потоков и договоров, здоровье обменов.
- ЕВКЛИД: единая витрина и ссылки на источник.
- Официальный мастер инвентарных ID и составов комплексов пока не установлен. Его нельзя подменять локальным ID ФАРВАТЕРА.

## Статус связей

В реестрах АТЛАСа `systems.json`, `flows.json` (срез 14.11.2026) и `contracts.json` (11 договоров C-01…C-11) ФАРВАТЕР отсутствует. Потоки ФАРВАТЕРА к СИЛЬВЕРу, АРХИМЕДу, ГЕРОНу, модулю утечек, РИТМу, МТР, TechDoc, АТЛАСу и ЕВКЛИДу являются новыми проектными связями и требуют владельцев данных, согласования схемы/прав/частоты и регистрации АТЛАСом. Никакую из них не описывать на сайте как работающую.

В экосистеме уже зарегистрированы независимые действующие потоки, в частности АДКУ → СИЛЬВЕР, потоки АРХИМЕДа → потребителям, СИЛЬВЕР/ГЕРОН/утечки → РИТМ в указанном для каждого потока режиме, а также журналы модулей → АТЛАС. Их действующий статус не означает, что они передают сведения ФАРВАТЕРУ.

## Разделение статусов

1. Поверка: действующая/истекает/истекла/нет данных/устаревший источник — только с доказательством и датой.
2. Применимость СИ и версии МИ к условиям — отдельная оценка с диапазоном, единицей, базисом и причиной.
3. Качество текущего сигнала — оценка системы-источника, не выводится из поверки.

## Локальная реализация после архитектурной сверки — 15.11.2026

В GasMeter локально добавлены отдельный polling-worker Яндекс Мессенджера, read-only поиск точных записей по заводскому номеру во внешнем публичном интерфейсе ФГИС «Аршин», маркированная PDF-копия публичных полей и экран/API «Метрологический эксперт» по локальным OCR-фрагментам МИ. Доступ бота проверяется по активной учётной записи GasMeter и роли. Выводы LLM не меняют расчёты и метрологические решения; неподтверждённые OCR-поля помечаются.

Это состояние исходного кода, а не запущенная интеграция: токен не внесён, polling-worker не запущен, связь с ФГИС из среды разработки не подтвердилась (сетевой тайм-аут), корпоративная LLM и ответы на реальных сканах не проверялись. PDF формируется приложением и прямо помечен как неофициальная копия; скачивание отдельного свидетельства из ФГИС не реализовано. Межсистемный публичный API ФАРВАТЕРА, синхронизация с сервером, регистрация потоков в АТЛАСе и публикация в ЕВКЛИДе остаются отдельными шагами.

Подробности: `docs/ФАРВАТЕР_Аршин_Мессенджер_и_эксперт.md`.

## Источники и ограничения

Архитектура основана на локальном GasMeter, реестрах АТЛАСа от 13–14.11, README СИЛЬВЕРа/АТЛАСа/ЕВКЛИДа, материалах ЦК_8 и двух документах ООО «ГазСервис». Коммерческие материалы описывают боты/возможные услуги, а не обязательные требования ИНК и не доказательство подключения к ФГИС «Аршин». Техническое состояние серверов не проверялось. АТЛАСом реестр не изменён; ЕВКЛИДом сайт не обновлялся; серверы не менялись.

## Следующие решения

Назначить мастер-источник инвентарных ID и поверки; определить официальный интерфейс поверки; выбрать первый контур/площадку; назначить владельцев МИ и контрактов; определить допустимые поля, права, SLA и срок уведомления «поверка скоро». Отдельно остаётся ранее отложенный выбор справочника месторождений/кустов.

**Дата следующей сверки:** перед публикацией страницы ЕВКЛИДа и перед каждым включением нового интеграционного потока сверить этот handoff и статусы в АТЛАСе. Дата календарного контроля владельцем не назначена.
