# ФОРВАТЕР 0.2.6 — целостность метрологических снимков

**23.11.2026.** Установлен на [АРХИМЕДе](http://10.224.120.1:8840) и [внешнем стенде](https://gasmeter.77-95-203-87.sslip.io). Перед обновлением обоих серверов выполнено резервное копирование БД и сохранены прежние образы для отката. Оба backend подтверждают версию 0.2.6, схему PostgreSQL 10 и 216 МИ. На АРХИМЕДе один снимок ИС Метрология на 48 312 строк; на внешнем стенде корпоративных снимков нет.

По результатам ревизии [0.2.5](РЕЛИЗ_ФОРВАТЕР_0.2.5.md) закрыты три ошибки:

1. Серверный API теперь отклоняет публикацию файла со строками, где невалидны идентификатор или дата, независимо от блокировки кнопки в браузере.
2. Новый файл с датой среза старше опубликованного и файл с датой в будущем отклоняются. Актуальный снимок определяется по дате среза, затем по времени импорта. Повтор того же SHA-256 остаётся идемпотентным.
3. В CSV экранируются текстовые поля, начинающиеся с символов формул Excel (`=`, `+`, `-`, `@`), включая ведущие пробелы. Строки по-прежнему содержат дату среза и источник.

Исправлена конфигурация Docker Compose для АРХИМЕДа: HTTP healthcheck относится к backend, а не к отдельному процессу бота. Проверено `docker compose config` для обоих сервисов. Бот на корпоративном сервере всё ещё не запущен и не подтверждён как действующий канал.

**Проверка:** 155 тестов прошли, включая запрос к API с ошибочным XLSX и сравнение последовательных снимков. На АРХИМЕДе повторно подтверждены поиск по заводскому номеру, 5 групп повторных GUID на 3 140 строк, CSV из 7 614 строк с прошедшей датой. На внешнем стенде backend, frontend, PostgreSQL и worker Аршина запущены; ФГИС остаётся недоступной из проверенных сетей, а состояние поверки не подменяется плановой датой из ТОиР.
