# ФОРВАТЕР 0.2.4 — приём периодических выгрузок

**23.11.2026.** Установлен на корпоративном АРХИМЕДе (`http://10.224.120.1:8840`) и внешнем стенде (`https://gasmeter.77-95-203-87.sslip.io`). Подтверждены версия 0.2.4, схема PostgreSQL 10 и 216 МИ. Корпоративная выгрузка 48 312 строк хранится только на АРХИМЕДе; на внешнем стенде импортов нет. Перед обновлением обоих серверов сделаны резервные копии БД, предыдущие образы сохранены для отката.

К возможностям [0.2.3](РЕЛИЗ_ФОРВАТЕР_0.2.3.md) добавлен автоматический приём **полных** снимков ИС Метрология на АРХИМЕДе. Задание `/etc/cron.d/gasmeter-metrology-inbox` проверяет входящую папку `/opt/gasmeter/data/metrology-inbox` ежечасно в 15 минут. Существующие задания cron не менялись. Cron активен, ручной запуск на пустой папке завершился без ошибок. На внешнем стенде это расписание не установлено.

Для каждого `имя.xlsx` требуется рядом `имя.json`:

```json
{
  "snapshot_date": "2026-11-20",
  "source": "ИС Метрология",
  "scope": "full",
  "sha256": "<64 символа SHA-256 исходного XLSX>"
}
```

Сначала передают XLSX, затем JSON: несогласованный или недокачанный файл не проходит сверку SHA-256. Импорт отклоняет частичный снимок, дату в будущем, дату старше уже опубликованной, файл больше 20 МБ и неправильный шаблон. Исходные файлы из папки не удаляются; копия опубликованного XLSX архивируется по хешу. Повторный запуск не дублирует снимок. Журнал работы: `/opt/gasmeter/backup/metrology-inbox.log`.

Для передачи с рабочего ПК манифест вручную составлять не нужно. После сохранения полной выгрузки запустить из `C:\projects\GasMeter`:

```powershell
& backend\.venv\Scripts\python.exe -m pip install -r scripts\requirements-deploy.txt
& backend\.venv\Scripts\python.exe scripts\send_metrology_snapshot.py 'C:\путь\к\выгрузке.xlsx' --snapshot-date 2026-11-23 --full
```

Скрипт проверяет структуру XLSX, дату, полноту, формирует SHA-256 и манифест, передаёт файл на АРХИМЕД через SSH с проверкой ключа сервера и сразу запускает импорт. Учётные данные читает из `C:\pass\izp-flow-meter.json`, не выводит их. На исходном файле из письма от 20.11.2026 полный цикл проверен дважды: оба раза ответ `already_imported`, число снимков осталось 1, число строк — 48 312. Следующая **новая** выгрузка ещё не предоставлена; её фактическое опубликование остаётся проверкой следующего цикла.

**Граница готовности:** автоматическая доставка новых файлов из 1С во входящую папку ещё не подключена. Для неё нужен владелец источника и согласованный порядок передачи. Это расписание не обращается в Аршин и не подтверждает факт поверки; оно публикует плановые данные выгрузки. Проверка сценария с новым боевым файлом возможна после его первой передачи.

Локально прошли 154 теста. На АРХИМЕДе повторно подтверждены 48 312 строк, поиск по номеру, 5 групп повторного GUID на 3 140 строк (в 3 группах различаются заводские номера) и CSV из 7 614 строк с прошедшей датой. Внешний стенд отвечает и не содержит корпоративного снимка.
